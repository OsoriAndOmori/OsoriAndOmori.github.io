AWS 연구, EC2 ALB EMR 등

Posted Dec 2, 2025 Updated Jun 30, 2026
By 오소리사냥꾼
2 min read

리전

  • IAM 은 리전을 선택하지 않는다.
  • 보통 다 리전을 고름. ec2 등등

가용영역 Availability Zone

  • 데이터 센터 라고 보면됨
  • 서울에 4개 있을 수도 있음.
  • 두 개 이상의 AZ 에 시스템 배치하면 고가용성을 보장하겠지, 판교, 강서에 한대씩~

엣지 로케이션 (Cloud Front, Global Accelerater)

  • 미국 - 서울 있을 때 CDN 같은 느낌으로 중간 캐싱하고 데이터 줌
  • 엣지 로케이션은 리전들과 고속 네트워크로 연결되어있음.

IAM

  • 사용자 그룹(Group) 역할(Role)
  • 사용자
    • 한 사람, 하나의 애플리케이에 대한 권한
    • 보안 -> MFA 설정

Https 설정하기

  • 옛날에 nfront 하듯이, ALB가 전담하게 시킬 수 있다.
    1. 인증서 만들기. AWS Certificate 가서 만들어
    2. ALB 생성. ec2 -> Loadbalancer
      • 하면서 여기에다가 규칙같은것 넣을 수 있고, 어떤 subnet 에 만들지 정할 수 있고 등등 https 인증서도 이식함
      • 일단 만들고 listener 추가 뒤 rule 변경하면 하나의 ip 로 개발, 스테이지, 상용 공유하면서 돈 절약 가능함.
    3. ec2 그룹으로 만들어놓고, target group 같은거 매칭해준다.

vpc subnet 네트워크

  • 핵심인데 정리하는 대로 추가 예정

사스 갖다쓰면 2배정도 비싸다

  • 내돈이면 ec2 받아서 직접 설치해야 할 듯.

Loadbalancer

  • Application Loadbalancer 는 vpc 대역만 같으면 어느 서브넷이건 전달 될 수 있다.
  • Network Loadbalancer 는 같은 vpc 는 당연하고, 같은 “Availability Zone” 에 있어야한다. 2a, 2b, 2c
    • 그래서 ec2와 잘 맵핑해서 셋팅해야한다.
    • 그럼 az 별로 ip 갯수가 소모되는데, dns 등록이 애매하면 CNAME 으로 등록하거나 route53 에서 alias 형태로 등록하면됨.
  • Security Group 으로 inbound 룰 정해야함. outbound 는 보통 전체 열어둠
