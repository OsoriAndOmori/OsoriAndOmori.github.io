2. 기초: 코어 / 프로세스 / 스레드 / 메모리 / 이벤트루프
- CPU 코어
  - 코어 하나는 한 순간에 하나의 명령만 실행한다 (동시성 vs 병렬성)
- 프로세스
  - 실행 중인 프로그램, 메모리 공간이 프로세스마다 따로
- 스레드
  - 프로세스 안의 실행 흐름, 같은 프로세스의 스레드끼리는 메모리를 공유한다
  - 코어에 스레드를 번갈아 태우는 것 (컨텍스트 스위칭)
- 메모리
  - 스택 / 힙, 프로세스 간 메모리는 공유되지 않는다
- 블로킹 vs 논블로킹, I/O 대기 중 스레드는 뭘 하나
- 이벤트루프
  - 스레드 하나로 여러 일을 번갈아 처리 (Node.js 와 같은 모델)
  - 코루틴 : 중간에 멈췄다가 이어서 실행할 수 있는 함수 (`async` / `await`)
  - 동기 코드가 이벤트루프를 막으면 다른 일이 전부 멈춘다
- 파이썬은 GIL 때문에 한 프로세스에서 파이썬 코드는 한 번에 한 스레드만 실행한다
  - I/O 대기 중에는 GIL 이 풀리므로 스레드가 I/O 에는 의미가 있다
  - CPU 를 여러 코어로 쓰려면 프로세스를 나눈다
- 실습) 같은 작업을 스레드 / 프로세스 / asyncio 로 돌려서 CPU 작업, I/O 작업 시간 비교

3. FastAPI 와 동기/비동기 (쉬운 것만, 실습 한 번으로 끝)
- FastAPI 맛보기 : hello → 간단 CRUD, `Depends`, pydantic 검증, `/docs` 자동 생성
- **`def` vs `async def`** ⭐ 이것만은 가져가기
  - `async def` → 이벤트루프에서 직접 실행, `def` → 스레드풀에서 실행
  - `async def` 안에서 동기 코드(`time.sleep`, `requests`, **boto3**)를 부르면 서버 전체가 멈춘다
  - boto3 는 동기(블로킹) 라이브러리다. FastAPI 가 비동기로 바꿔주는 게 아니라, `def` 로 쓰면 스레드풀에서 돌려줘서 **다른 요청을 막지 않을 뿐**이다
  - 호출 자체는 여전히 블로킹이고, 동시 처리 상한은 스레드풀 크기(기본 40)
  - Tomcat 워커 스레드풀과 비슷한 느낌 (요청 하나 = 스레드 하나). 다만 `async def` 는 스레드풀이 아니라 이벤트루프 스레드에서 돈다는 점이 다르다
  - 그래서 "async 붙이면 빨라진다" 는 오해
- 실습) 같은 boto3(localstack S3) 호출을 `async def` / `def` 두 가지로 만들고 동시 요청 10개 던져서 시간 비교
- 멀티프로세스는 개념만 : uvicorn `--workers N` 하면 프로세스가 N개, 각자 이벤트루프 + 스레드풀을 따로 가진다
  - 실습) 응답에 PID 찍어서 분산되는 것만 확인
- 나중에 더 파볼 것 (지금은 이름만 알아두기) : GIL, `asyncio.to_thread`, `aioboto3`, boto3 커넥션 풀(`max_pool_connections`), fork 이슈

4. DB
- 데이터 설계 : 한 테이블에 다 때려넣기 vs 교과서대로 테이블 분리
  - 장단점 생각해보기 (정규화와 역정규화)
  - 정규화
- Transaction
  - ACID
  - commit, rollback
- [isolation](https://joont92.github.io/db/%ED%8A%B8%EB%9E%9C%EC%9E%AD%EC%85%98-%EA%B2%A9%EB%A6%AC-%EC%88%98%EC%A4%80-isolation-level/) 실습
- 테이블, 컬렉션 index 는 어떻게 설정해야 할까
  - cardinality 와 b+트리
  - 실행계획(`EXPLAIN`)
- SQLAlchemy 동기 vs async (`asyncpg`, `aiomysql`), 세션 스코프를 요청 단위로
- **커넥션 풀 크기 산정** : 워커 수 x 풀 크기 <= DB max connections

5. 인증
- OAuth 2.0
- 가장 일반적인 AUTH_CODE 방식 다이어그램
  ```
         [ 브라우저 (사용자) ]                  [ 내 백엔드 서버 ]                           [ OAuth 인증 서버 ]
                   │                                     │                                             │ (구글/카카오 등)
  1단계 인증       │── 1. ID / PW 전송 (HTTPS) ───────────────────────────────────────────────────────>│
                   │                                     │                                             │ (신원 검증, 동의 확인)
                   │<─ 2. 302 Redirect (Location: callback?code=AUTH_CODE) ────────────────────────────│
                   │                                     │                                             │
  2단계 코드전달   │── 3. GET /callback?code=AUTH_CODE ─>│                                             │
                   │                                     │                                             │
  3단계 토큰교환   │                                     │── 4. POST /token (code + Secret Key) ──────>│
                   │                                     │                                             │ (code, Secret 검증)
                   │                                     │<─ 5. Access Token 응답 ─────────────────────│
                   │                                     │                                             │
  4단계 자체JWT    │                                     │ [사용자 정보 조회 & 회원가입]               │
                   │                                     │ [자체 서비스용 JWT 발급]                    │
                   │                                     │                                             │
  5단계 정착       │<─ 6. 최종 응답 ─────────────────────│                                             │
                   │ 방식 A: Set-Cookie 에 JWT 포함      │                                             │
                   │ 방식 B: JSON 본문에 JWT 반환        │                                             │
                   ▼                                     ▼                                             ▼
  ```

6. 캐시와 타임아웃
- 로컬 캐시 (`functools.lru_cache`, `cachetools`) vs 글로벌 캐시 (Redis)
  - **멀티 프로세스에서 로컬 캐시의 함정**
- 각 구간 타임아웃 : httpx / boto3 / DB / uvicorn / LB
  - 클라이언트에서 서버로 갈수록 타임아웃은 어떻게 배치해야 하나
- `asyncio.timeout` 과 취소 전파 (스레드로 넘어간 블로킹 호출은 취소가 안 된다!)

7. Web / Proxy / 배포
- 리버스 프록시(nginx / ALB), uvicorn 을 직접 노출하면 안 되는 이유
- Docker : 이미지 만들기, 멀티스테이지, 컨테이너 CPU 제한과 워커 수
  - 컨테이너 안 `os.cpu_count()` 함정
- 배포 전략 rolling / blue-green / canary, Health check, graceful shutdown
- 실제 2대(or 컨테이너 2개)로 무중단 배포 해보기
- 시간 남으면 k8s
